# 审批中心 Agent 接入方案

> 状态：方案，尚未实施。本文基于 `backend/docs/AI平台与外部业务系统交互说明.md` 和当前审批中心代码，约定第一阶段的产品行为、接口边界及落地顺序。Agent 数量、路由切换和工具授权以同目录《Agent配置与工具清单.md》为准。

## 1. 目标与范围

第一阶段由常态助手覆盖普通页面，并在下列详情页提供两项专属能力：

| 页面 | 快捷入口 | 首条自动消息 | 后续交互 |
| --- | --- | --- | --- |
| 工作台审批详情 | AI 总结 | 总结当前审批单，列出依据、待确认点和非约束性审批建议 | 可继续追问；同意、拒绝仍由人点击原有按钮 |
| 工作台抄送详情 | AI 总结 | 总结当前审批单和流转情况，列出关注点 | 可继续追问；页面保持只读 |
| 审批流详情 | 解读审批流 | 说明流程、现有版本和草稿情况 | 可继续追问；进入草稿编辑页后再生成和应用 |
| 审批流版本编辑 | AI 生成审批流 | 根据用户描述生成候选流程图和表单 | 可多轮修改；先预览，再由用户应用到草稿 |

三个 Agent 都使用 AI 平台的**普通多轮会话**。普通页面保持常态助手；进入审批流详情或版本编辑页切到流程设计助手，进入工作台审批或抄送详情切到审批单助手。切换页面只切换 Agent 与会话作用域，不自动发送消息。按钮是“打开统一聊天面板、创建新会话、发送预设消息”的快捷入口。用户也可以在面板中打开当前对象的历史会话或主动新建会话。不同对象之间绝不复用同一个 `conversation_id`。

本阶段不让 Agent 自动审批、拒绝、保存或发布流程。AI 生成内容和审批建议均须由用户审阅。

## 2. 用户交互

### 2.1 共用聊天面板

- 页面内有清楚的入口，点击后展开右侧面板；面板包含消息流、输入框、新会话、当前对象的历史会话和错误重试。
- 普通页面提供常态助手，跨普通页面保留其会话；进入流程或工作台详情页时按路由切到专属 Agent，离开后恢复常态助手。
- “AI 总结”点击后立即创建新会话并发送预设消息。重复点击会创建另一段会话；用户可从历史列表找回之前的结果。
- “AI 生成审批流”先让用户输入自然语言需求，再创建新会话并发送。后续“把第二级改成会签”等修改沿用该会话。
- 面板标题始终带场景和对象名称，例如“审批单 AI 助手 · 采购申请”或“流程生成 · V3 草稿”。切换审批单或流程版本时切换会话列表。
- SSE 流式展示回答；运行中禁用同一会话的重复发送，断线显示明确状态并允许用户查询历史结果。不得把网络断开解释为已取消 Agent 运行。

### 2.2 审批单总结

- 后端按审批单 ID 重新读取当前表单、对应版本的字段显示名、状态、节点流转与审批意见，整理为有长度上限的可信上下文。前端不提交可伪造的整张表单内容。
- 提示词要求区分“已知事实”“待确认信息”“建议及理由”；缺少依据时明确写出，不编造审批规则。建议须标注“仅供参考”。
- 抄送详情使用同一个聊天组件和总结 Agent，但场景为只读；不在 AI 消息中提供代为审批入口。
- 点击原有审批按钮仍调用现有审批接口，AI 会话不参与审批状态变更。

### 2.3 审批流生成

- 后端向 Agent 提供当前草稿、启用的节点定义及配置 Schema、可选人员及审批表单约束。自然语言需求是用户消息，不直接拼成具有系统权限的指令。
- Agent 返回候选流程说明和结构化流程提案。提案包含逻辑节点、节点类型、配置、条件连线、表单字段及未能确定的问题；不得把模型生成的数据库 ID 当作可信引用。
- 后端把节点类型映射到当前启用的节点定义，生成实际 UUID，解析人员引用，并复用现有流程结构校验规则。校验不通过时返回逐项问题供用户继续修改。
- 前端在画布上预览候选图及与当前草稿的差异。默认操作是“替换当前草稿内容”，必须明确提示影响范围；不做隐式合并。用户确认后才写入编辑器工作副本，仍需显式“保存草稿”和“发布”。
- 应用前比较生成所依据的 `revision` 与当前编辑器修订号；页面有未保存改动时先要求用户处理或明确选择覆盖范围。后端保存继续使用原有乐观锁。已发布版本不显示应用入口。

## 3. 系统边界与目录

```text
web-vue/src/components/ai/         # 前端共用聊天面板、消息和候选图预览
web-vue/src/api/modules/ai.ts       # 只访问审批中心自己的 AI 网关

app/server/ai/
  api/                         # 管理端 AI 路由、请求校验、SSE 转发
  src/config/                  # AI 平台地址、Agent ID、固定管理员 ID 等配置
  src/client/                  # AI 平台 HTTP/SSE 客户端
  src/service/                 # 上下文构建、会话绑定、流程提案转换与校验
  src/schemas/                 # 本系统请求/响应和流程提案结构
  src/models/、src/repository/  # 仅保存本地会话与业务对象绑定
  docs/                        # 本方案及后续接口说明
```

所有**后端 AI 专属实现**放在 `app/server/ai`。`app/main.py` 仅注册该模块路由；审批流与审批实例模块继续提供原有领域服务，不把 AI 编排逻辑散落进去。前端页面仅接入入口和展示组件。AI 平台保存消息、运行时间线和 Checkpoint；审批中心不再复制一份完整聊天记录。

## 4. 身份、配置和会话绑定

当前是管理员控制台，第一阶段后端固定使用 `external_user_id = approval_admin`。这个值来自服务端配置，浏览器不能传入或覆盖。AI 平台的 `X-API-Key`、地址、三个 Agent ID 与独立的 AI Tool 凭证同样只在后端配置，不写入前端、URL、日志或仓库。建议配置项为：

```text
AI_PLATFORM_BASE_URL
AI_PLATFORM_API_KEY
AI_GENERAL_AGENT_ID
AI_SUMMARY_AGENT_ID
AI_FLOW_AGENT_ID
AI_TOOL_KEY
AI_EXTERNAL_ADMIN_USER_ID=approval_admin
AI_REQUEST_TIMEOUT_SECONDS
```

本系统 AI 路由沿用现有 `X-Admin-Key` 管理端鉴权。固定管理员 ID 意味着持有管理权限的操作员共用 AI 平台的用户身份和历史；这是当前阶段的明确取舍，日后接入个人登录时应改为稳定的个人 ID，并迁移或隔离旧会话。

本地仅保存会话绑定：`conversation_id`、`agent_id`、场景（`GENERAL` / `APPROVAL_SUMMARY` / `COPY_SUMMARY` / `PROCESS_DETAIL` / `FLOW_GENERATION`）、业务对象 ID（常态场景为空，其余为流程、审批单、抄送任务或版本 ID）、创建时间、最近活动时间和生成时的草稿 `revision`。每次继续对话或查历史前，后端检查该绑定，防止把同一个固定管理员身份下的另一张审批单会话误用到当前页面。会话 ID 由 AI 平台首次响应产生，本地绑定不得凭前端自行声明建立。

抄送入口还须核对抄送任务与审批单的关系；`person_id` 只用于定位记录，不能当作登录身份。当前管理端用管理密钥访问，后续若切为个人端须重新引入真实用户权限校验。

## 5. 与 AI 平台的协议

审批中心后端调用 AI 平台 `POST /agent/messages`，请求头包含平台的 `X-API-Key`。首次发送 `conversation_id: null`，后续沿用 AI 平台返回的 ID。`external_user_id` 始终由后端填写。普通文本请求使用 `message_type: text`、`stream: true`、`file_ids: []`。

```json
{
  "agent_id": "由后端场景配置选择",
  "external_user_id": "approval_admin",
  "conversation_id": null,
  "message": "请总结当前审批单并提出供人工参考的建议",
  "message_type": "text",
  "stream": true,
  "additional_system_context": "由后端读取和裁剪的当前业务上下文",
  "inputs": {
    "scene": "APPROVAL_SUMMARY",
    "object_id": "当前对象 ID"
  },
  "file_ids": []
}
```

前端只调用审批中心的 AI 网关。网关消费 AI 平台 SSE，向前端转发 `run_start`、`model_delta`、`run_end`、`error` 等必要事件，并提取 `conversation_id` 建立绑定。历史列表和消息分别代理 `POST /agent/conversations/search`、`POST /agent/conversations/messages`；历史消息的 `structured_content` 用于还原可见回答和运行状态。第一阶段若不展示思考或工具细节，仍应保留可扩展的事件结构。

首次编码前需用 AI 平台实际响应样例核对 SSE 事件载荷、`conversation_id` 出现位置、历史消息结构及错误格式；提供的说明文档约定了事件名和接口用途，但没有逐字段响应 Schema。不要按猜测编写解析器。

常态助手通过 AI 平台 MCP Tool 查询实时列表，两个专属 Agent 使用各自授权的只读或校验 Tool。具体 9 个工具、挂载关系和独立 Tool 凭证见《Agent配置与工具清单.md》。按 AI 平台文档，由审批中心后端通过 `X-Business-Authorization` 提供本次运行的 Tool 凭证，再由 FastMCP 按 `business_token_header` 透传给受控 AI Tool API；不把管理端 `X-Admin-Key` 配进 AI 平台。当前页面对象的摘要上下文仍由可信后端构造。所有 Agent 均不授予“保存草稿”“发布”“审批决策”工具。

## 6. 审批中心建议提供的接口

接口均位于 `app/server/ai/api`，统一走现有管理密钥鉴权；具体响应体以实现时的 Pydantic Schema 为准。

| 接口 | 用途 |
| --- | --- |
| `POST /api/admin/ai/conversations` | 按场景和对象新建会话并发送首条消息，返回 SSE |
| `POST /api/admin/ai/conversations/{id}/messages` | 在已绑定会话中继续发送消息，返回 SSE |
| `GET /api/admin/ai/conversations` | 按场景和对象筛选历史会话 |
| `GET /api/admin/ai/conversations/{id}/messages` | 查询并回放历史消息 |
| `POST /api/admin/ai/flow-proposals/{id}/preview` | 解析和校验某次 AI 输出，返回候选图及问题，不写草稿 |

`preview` 中的 ID 指 AI 运行结果或消息 ID，不能让浏览器提交任意 JSON 假装成 AI 输出。应用候选图优先由前端把已校验结果写进编辑器工作副本，再由用户使用现有 `PUT /api/admin/process-versions/{version_id}/graph` 保存；如需服务器签发不可篡改的预览令牌，实施时可在 `app/server/ai` 增加短期预览记录，不改变“用户确认后才保存”的原则。

## 7. 校验、错误与数据边界

- 审批单上下文只取当前对象所需字段，限制体积；敏感字段按业务规则脱敏。AI 平台会持久化用户消息和回答，因此发送前应明确字段范围。
- 生成结果须经过结构解析、节点定义与配置检查、人员引用检查、表单 Schema 检查、连线/分支/可达性检查。复用 `process_validation.py` 和现有保存服务，不能只依赖 Agent 提示词。
- AI 平台超时、断流、`401/403`、模型错误和结构无效分别给出可理解的状态。失败时不改变审批单或编辑器草稿。
- SSE 长请求不持有数据库事务。读取业务上下文和会话绑定用短事务，关闭后调用 AI 平台，结束后再单独更新绑定。
- 日志记录场景、对象 ID、会话 ID、耗时和错误类别；不记录完整 AI 平台 Key、管理密钥、业务 Token 或整张审批表单。
- `additional_system_context` 只由可信后端构造；用户原话始终作为普通 `message`。每次追问重新附上当前对象上下文，避免上下文过时。
- 新会话和继续发送应限制同一对象的并发请求；失败后的重试先查询运行/历史，避免一次点击重复创建多个会话或重复生成提案。

## 8. 实施顺序与验收

1. 在 AI 平台创建业务平台并签发 API Key；配置三个绑定该平台的普通会话 Agent 和九个受控 Tool，按《Agent配置与工具清单.md》授予各 Agent。
2. 在 `app/server/ai` 建立配置、平台客户端、会话绑定与只读历史代理；用 AI 平台真实响应样例确认 SSE 解析。前端接入共用聊天面板。
3. 接入常态助手的列表查询，以及审批详情和抄送详情的“AI 总结”；验证页面切换、不同对象的会话隔离、抄送只读和原有审批操作。
4. 定义流程提案 JSON 契约及转换校验，接入流程详情解读和编辑页的预览、确认应用、版本冲突提示；继续沿用现有保存和发布操作。
5. 完成后端单元/接口测试、前端类型和构建检查，并用真实 AI 平台做一轮端到端验收。未配置 AI 平台时页面显示“AI 功能未配置”，原审批功能正常可用。

验收标准：点击快捷入口能发起新会话；追问能沿用会话；历史只出现在对应对象；审批建议不能直接改变审批状态；流程提案校验不通过不会写草稿；预览和应用需要用户操作；发布仍由现有发布入口完成。

## 9. 实施前仍需取得的配置与样例

- AI 平台可访问的服务地址、平台 API Key 与独立 Tool 凭证的安全配置渠道、常态/总结/流程三个 Agent ID。
- AI 平台 `stream=true` 的真实 SSE 样例和会话历史响应样例，尤其是 `conversation_id` 与结构化内容字段。
- 流程 Agent 能否稳定返回机器可解析的结构化结果；若平台有专门的结构化输出能力，应优先使用，并据此固定提案 Schema。

这些信息用于实施与联调，不影响本方案的目录和职责划分；API Key 不应写入文档或聊天记录。
