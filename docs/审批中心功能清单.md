# 审批中心功能清单

> 最后更新：2026-09-23  
> 当前原则：先完成并验收最小业务闭环，再按优先级逐步增加功能。

## 一、当前闭环目标

选择一个真实业务场景，例如付款申请，完整走通以下链路：

```text
创建租户并配置接入凭据
    → 维护人员
    → 创建并发布审批流
    → 给租户授权审批流和业务动作
    → 业务系统通过 API 发起审批
    → 审批人查看审批单并处理任务
    → 审批流结束
    → 审批通过后回调业务系统
    → 查询审批过程和回调结果
```

只有这条链路在同一个环境中完成端到端验证，当前阶段才算真正闭环。

## 二、闭环必需功能清单

### 2.1 基础配置

- [x] 创建、查询、修改和停用租户。
- [x] 为租户签发 API Key。
- [x] 为租户配置回调基础地址和 Service Token。
- [x] 手工维护人员和部门基础数据。
- [x] 维护人员与租户的绑定关系。
- [x] 创建、保存、发布和查询审批流。
- [x] 配置审批节点、审批人、节点关系和分支条件。
- [x] 用「条件分支」节点承担分流：节点内配置 if/elif/else 阶梯，每条分支有自己的出口。
- [x] 分支的条件和去向分开配：节点弹窗里只配条件，每一行右侧的圆点拖线到目标节点定去向。
- [x] 连线中点有断开入口：普通连线整条删除，分支连线只清空去向（分支和条件保留）。
- [x] 将审批流授权给租户使用。
- [x] 创建业务动作并配置请求方法、相对路径、校验规则和超时时间。
- [x] 将业务动作授权给租户使用。

### 2.2 发起审批

- [x] 业务系统使用 API Key 确定租户身份。
- [x] 发起请求指定 `process_id`、`business_key` 和可选的 `action_code`。
- [x] 校验租户是否有权使用审批流和业务动作。
- [x] 保存审批单展示数据和业务执行参数。
- [x] 审批实例绑定发起时的已发布流程版本。
- [x] 创建首个节点执行记录和首批审批任务。
- [x] 使用幂等键防止同一业务申请被重复发起。

### 2.3 审批处理

- [x] 查询审批人的待办任务和已办任务。
- [x] 查看审批单数据、当前状态和审批时间线。
- [x] 审批人可以同意或拒绝任务。
- [x] 支持多人并行审批。
- [x] 支持 `AND` 和 `OR` 通过规则。
- [x] 任意审批人拒绝时当前审批节点拒绝。
- [x] 根据流程编排推进后续节点并进入最终状态。
- [x] 保存每一次审批操作、意见和处理时间。

### 2.4 审批结束与业务执行

- [x] 审批通过且存在 `action_code` 时创建唯一业务执行记录。
- [x] 审批拒绝或未配置 `action_code` 时不调用业务接口。
- [x] 后台 Worker 领取 `PENDING` 执行记录并调用业务系统。
- [x] 使用租户 Service Token 构造业务系统认证请求头。
- [x] 保存请求地址、响应状态、响应内容、失败原因和处理时间。
- [x] 服务正常关闭时等待已经进入 `RUNNING` 的任务完成。
- [x] 未领取的任务在服务关闭后继续保持 `PENDING`。

### 2.5 查询与核对

- [x] 根据审批实例 ID 查询审批详情。
- [x] 查询节点执行、任务和审批记录组成的时间线。
- [x] 查询业务执行记录及其最终结果。
- [x] 失败时能够看到明确的错误原因。
- [ ] 使用一个真实业务接口完成一次端到端联调（等待业务系统开发完成）。
- [ ] 完成闭环验收用例并保存验收结果。

## 三、闭环验收用例

当前阶段至少完成以下场景：

| 编号 | 验收场景 | 预期结果 | 状态 |
| --- | --- | --- | --- |
| E2E-01 | 单人审批通过 | 审批状态为 `APPROVED`，业务回调成功 | 未验收 |
| E2E-02 | 单人审批拒绝 | 审批状态为 `REJECTED`，不创建业务回调请求 | 未验收 |
| E2E-03 | 多人 `AND` 审批 | 所有人通过后才推进，任意一人拒绝即拒绝 | 未验收 |
| E2E-04 | 多人 `OR` 审批 | 任意一人通过即可推进，任意一人拒绝即拒绝 | 未验收 |
| E2E-05 | 业务回调失败 | 审批仍为通过，执行状态为 `FAILED` 并保存原因 | 未验收 |
| E2E-06 | 重复发起同一业务申请 | 幂等规则阻止产生重复审批实例 | 未验收 |
| E2E-07 | 执行期间正常关闭服务 | 等待 `RUNNING` 任务完成，未领取任务保持 `PENDING` | 代码测试已通过 |

- [ ] 确定文件存储方案，例如对象存储或上层项目平台文件服务。
- [ ] 提供上传、下载、预览和删除接口。

## 六、范围控制规则

- 当前只修复阻塞闭环的问题，不在闭环验收前扩展新模块。
- 新想法先登记到本清单，不立即改变当前开发范围。
- 闭环验收完成后，从“闭环完成后优先增加的功能”中逐项设计和开发。
- 每项功能仍按“方案确认、表结构、接口、实现、测试、文档”的顺序落地。
